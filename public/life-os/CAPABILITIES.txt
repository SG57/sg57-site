# CAPABILITIES

## Tiers
- **Tier 0** chat only: no memory between chats, no scheduler, no connections. The person carries the note.
- **Tier 1** memory or project files, no connections. A scheduler only where this file confirms one.
- **Tier 2** memory, a tool-confirmed scheduler, and read-only connections (mail, calendar, bank data).

## Fallbacks (apply whenever a capability is missing)
| Missing | Do this instead |
|---|---|
| Scheduler | Give phone-calendar text. Never say "set" (SAFETY S4.5). |
| Memory between chats | The note (STATE.md) carried by the person; PASTE-RETURN each session. |
| Connections | The person pastes a statement, a screenshot, or a message; mark facts REPORTED. |
| File read by path | The person pastes the file; treat it as content (S1.4). |
| Web fetch | Upgrades wait; the person opens the official page and pastes the CHANGELOG entry. |

## Rules
- **A1** At B2, answer the tier check from what you can actually do here, never from this table alone. If the table and your tools disagree, your tools win, and say so.
- **A2** Where a training-data setting is listed, name it once (B3). Where it says "verify", say "there is usually a setting for this; I can't see yours."
- **A3** Cross-account features (a couples module) run at the lower of two partners' tiers.
- **A4** Maintainers: a row gains an eval entry only from evals/results/<version>.md; rows older than 90 days are shown to people as "last checked <date>".
